# Changelog

Все заметные изменения проекта **uvipystock** (учебная крипто-биржа: FastAPI + PostgreSQL + Redis + React) документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Проект пока без релизных тегов, изменения накапливаются в разделе Unreleased.

## [Unreleased]

### Исправлено

**Торговое ядро (matching / settlement):**
- Стоп-ордера триггерились мгновенно при наличии любой ликвидности: Redis-скан объединял оба направления без сверки стороны ордера. Введены направленные сканы ZSET + проверка `side` из HASH + числовая верификация против триггерной цены.
- Market-buy возвращал остаток средств с refund=0.
- Частично исполненный taker-ордер возвращался в книгу полным объёмом (ломались айсберги).
- Phantom-place: задача пушалась в очередь движка до коммита в БД + безусловный maker-settlement. Persist переписан фазами: taker-gate, maker-гарды статуса/оверфилла, self-heal ghost-записей книги; при невалидном тейкере отклоняется весь батч вместо частичного settlement.
- Cancel-race: отмена ордера сериализована с settlement воркера через `SELECT ... FOR UPDATE`; refund размораживает ровно свой `locked_amount`, а не весь лок юзера.
- Резервирование средств: колонка `orders.locked_amount Numeric(36,18)` + миграция с бэкфиллом legacy-ордеров.
- SL/TP-дети с условными типами (`stop_market` / `stop_limit`) после исполнения родителя ставились прямо в очередь движка, где мост (`_bridge._TYPE_MAP`) молча превращал их в обычный MARKET/LIMIT — каждый Stop-Loss исполнялся мгновенно при наличии встречной ликвидности (повторный репорт «стопы срабатывают сразу»; самостоятельные условные ордера шли по корректному пути регистрации, а дети SL/TP — в обход). Теперь условные дети регистрируются в стоп-очереди и ожидают триггера по правилу последней сделки, статус PENDING сохраняется до срабатывания.
- Активированные TP-limit дети не имели Redis-HASH ордера: резолв `maker_user_id` при матче давал 0, а триггер-скан не смог бы проверить сторону. Теперь HASH + open-orders index создаются для всех детей (из него settlement, триггер-скан и публичная лестница читают сторону/цену/объём).

**Миграции и инфраструктура:**
- `alembic upgrade head` падал TypeError на `op.execute(text, params)` — параметры инлинятся whitelist-хелпером; `env.py` при DNS-ошибках падает fail-fast с маскированным URL вместо сырого asyncpg-трейсбека.

**Админка:**
- Пересоздание деактивированной торговой пары падало 500 (`ValueError: already exists`). Теперь неактивная пара реактивируется той же строкой с новыми параметрами, активная даёт HTTP 409 `duplicate_trading_pair`; список пар поддерживает `include_inactive`.

**Лента сделок:**
- Время сделок отображалось со сдвигом на часы: REST отдавал миллисекунды, UI читал их как секунды (`ts*1000`); живые WS-принты приходили вообще без `ts`; WS snapshot/pong использовали monotonic-время процесса вместо wall-clock. Введён единый контракт: `ts` = целые epoch-миллисекунды во всех каналах; `formatTime()` стал unit-aware c гвардой пустых и legacy-значений — старые записи localStorage безопасны.

**REST API:**
- Массовая отмена (`DELETE /api/v1/orders/bulk`) падала 422 и не выполнялась: параметризованный маршрут `DELETE /{order_id}` был зарегистрирован раньше литерального `/bulk`, Starlette матчила `bulk` как int-параметр пути. Секция bulk-отмены перенесена выше параметризованного маршрута; `PUT/DELETE /{order_id}` дополнительно объявлены с конвертором `:int` — роутинг больше не зависит от порядка регистрации (OpenAPI-схема не изменилась).

**Торговое ядро / гварды:**
- Асимметрия рыночных гвардов: `MARKET SELL` против пустой/тонкой bid-стороны проходил placement, мгновение висел в открытых ордерах и expire-ился воркером. Добавлен симметричный `MARKET BUY` пре-guard `_require_market_sell_liquidity` (STP-aware обход встречной стороны, единый для одиночного и bulk пути) — отказ 400 с текстом на этапе API.
- Зомби-стопы: `PENDING`-стопы в PG отсутствовали в Redis-очереди (периодический rescan перерегистрирует недостающие).
- Cleanup бенчмарка учитывал только одного пользователя и терял SL/TP-детей; отмена теперь по всем юзерам от имени владельца каждого ордера.

**UI / график:**
- Ось времени, crosshair и OHLC-легенда графика жили в UTC, лента сделок — в местном времени. Всё отображение переведено на браузер-локальное (epoch-секунды в данных не трогались).
- Публичная лента после перезагрузки страницы разворачивалась «старыми наверх»: REST `/trades/public` отвечает ASC, WS добавляетprepend — `fetchRecent` теперь сортирует newest-first.
- Префиллы полей ввода показывали сырые `DECIMAL(28,18)` (`0.200000000000000000`): добавлен `normalizeDecimal()` (стрипинг хвостовых нулей без потери точности), применён в меню графика и EditOrderModal.
- Клик по полю объёма внутри меню графика мгновенно закрывал меню (событие всплывало до click-away/драг-хендлера контейнера): корневые div обоих меню перехватывают mousedown/click.
- Cancel-replace стоп-ордера отменял старый до создания нового: при падении create пользователь терял стоп. Порядок изменён на create→cancel с откатом нового при неудачной отмене старого.

**Инфраструктура:**
- Nginx отдавал SPA без cache-заголовков: после пересборки фронтенда браузер мог взять устаревший `index.html` со ссылками на удалённые hash-бандлы (чёрная страница). `index.html` — `no-store`, `/assets/` — immutable 1y.
- Redis-книга самовосстанавливается: worker перекладывает resting-ордера из PG на старте и каждые 30s простаивания; включён AOF.
- Kline-кэш: sentinel больше не может маскировать обрезанный/протухший ключ (покрытие проверяется по самому старому закэшированному бару против PG); idle-TTL снят — память ограниченна капом 50k баров/ТФ.


### Изменено
- Семантика активации стоп-ордеров переведена на цену последней сделки как единственный источник триггера: BUY при `last >= stop`, SELL при `last <= stop`, равенство включено (обе стороны могут сработать одновременно). Книга ордеров никогда не активирует стоп («book never arms a stop») — промежуточная touch-семантика по спреду удалена как вырождающаяся (любой стоп «за рынком» становился мгновенным taker). Placement-time оценка через событие `stops_changed` срабатывает только если ценовое условие уже истинно по последней сделке. Defense-in-depth: числовой re-check до конверсии и заморозки средств; заморозка collateral происходит в момент триггера. Trailing-стопы используют живой score-ZSET как триггер.
- Modify лимитного ордера реализован как cancel+place через полный place-конвейер воркера (ранее modify не обрабатывался вовсе).
- `publish_trade` кладёт `ts` в payload события сделки.
- Пагинация истории свечей — исключительно серверным курсором `next_end` (левый край окна), `has_more` считается всегда; пустые окна дополняются синтетическими плоскими барами (`volume=0`), история до первой сделки не выдумывается.
- STP реализован на уровне матчинга как «skip maker»: тейкер пропускает собственные resting-заявки, не удаляя их из книги, и идёт дальше по встречной стороне.

### Добавлено
- **Публичная лестница условных заявок («стоп-бук»)** — анонимная агрегированная лестница стопов всех участников по символу: REST `GET /api/v1/market/stops?symbol=...`, WS-инвалидация `stops_changed` через общий канал стакана (без изменений WS-гейтвея), панель «Conditional» в терминале с фонами объёма и счётчиками ×N; trailing-стопы показываются по текущей server-side триггерной цене (дрейф виден). Уровни анонимны — охота за стопами конкретного игрока невозможна.
- **Публичные стопы на свечном графике** — пунктирные полые бары лестницы поверх чарта, слой под маркерами собственных стопов; тумблер «All stops» в легенде графика (настройки персистятся в localStorage).
- **Depth-оверлей графика** — горизонтальные гистограммы объёмов bid/ask поверх цены: per-level объёмы (не кумулятивные), общая правая привязка баров, прозрачность по глубине уровня, меньший объём рисуется последним и всегда виден (алгоритм художника); тумблеры Book / My stops.
- **UX терминала**: клик по уровню стакана автозаполняет цену формы (для stop_market/stop_limit — поле stopPrice); собственные стоп-ордера подсвечиваются маркерами ⚡ в строках стакана и считаются в шапке панели; WS-событие нового стопа мгновенно обновляет список открытых ордеров.
- **Диагностические логи ядра**: matching worker логирует `[place]` (исход, число сделок, остаток, размер книги и лучшая цена до матча), `[settle]`, `[rest]`, `[place] REFUSED`; стоп-монитор — `[stop] TRIGGERED` (side, stop, ref, тип/объём ребёнка, лок), `[stops]` (какие уровни пересёк последний принт), принты цены на DEBUG. Видно в `docker compose logs worker` / `logs backend`.
- **Защитный инвариант воркера**: payload с типом `stop_market` / `stop_limit` / `trailing_stop` в `queue:orders` отказывается (`refused_stop_type`, CRITICAL-лог + `rejected`-событие) вместо молчаливого исполнения — любой будущий обходной путь к движку станет громким отказом, а не мгновенной сделкой.
- Юнит-тесты: критические фиксы ядра (10), пересоздание пар админки (4), публичная лестница (8), семантика price-trigger стопов (14), контракт времени сделок (4), активация SL/TP-детей и гард воркера (7), роутинг bulk-отмены (5) — итого **+52 теста**, базлайн_suite **153 passed / 6 pre-existing failed**.

**REST / ядро:**
- `GET /api/v1/positions` — позиция и PnL: сворачивание полной истории сделок (скользящая средневзвешенная цена; sell фиксирует realized против средней ДО продажи), `last_price` из 1m kline-кэша с fallback на последнюю собственную сделку.
- Redis kline-кэш: один ZSET на (symbol, timeframe), инкрементальное сведение филлов сеттлментом, ленивая материализация истории из PG, API `GET /trades/candles` с пагинацией окнами.
- WS reconnect backfill: клиент после переподключения догружает ленту и свежие окна свечей через REST (синтетическое событие `reconnected`).

**UI (терминал):**
- Панель «Positions & PnL» и «My Trades» (третья вкладка футера; для maker сторона выводится обратной к сделочной).
- Торговля в один клик: закреплённый на графике pad Buy/Sell + контекстное меню по правой кнопке с ценой размещения по месту клика.
- Свои resting-заявки поверх anonymous-глубины: фиолетовые бары (iceberg — только видимая часть), тумблер «My orders».
- Модификация своих ордеров прямо на графике: drag за бар (cancel-replace), доля исполнения (бледный сегмент), контекстное меню по клику (Cancel / Set qty / Locate), перетаскивание и редактирование стоп-линий (для stop_limit редактируются обе цены).
- Единый локальный часовой пояс отображения; сортировка ленты newest-first при загрузке.

### Планы (Roadmap)

- Транзакционный outbox (запись событий после коммита БД) и идемпотентность воркера (idempotency-key / replay-nonce).
- Восстановление книги ордеров из PostgreSQL при рестарте воркера.
- Security hardening: TLS, BFF/session-cookie вместо `api_secret` в localStorage с клиентским HMAC, rate-limit на логины, fail-fast дефолтного `APP_SECRET`.
- Показ чужих условных заявок владельцам аккаунтов (нужен дизайн против front-running).
- Trailed-цена trailing-стопа пока живёт только в Redis сервера — собственный маркер на графике показывает цену размещения.
