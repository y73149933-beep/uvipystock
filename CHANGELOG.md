# Changelog

Все заметные изменения проекта **uvipystock** (учебная крипто-биржа: FastAPI + PostgreSQL + Redis + React) документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Проект пока без релизных тегов, изменения накапливаются в разделе Unreleased.

## [Unreleased]

### Исправлено

**Торговое ядро (matching / settlement):**
- Стоп-ордера триггерились мгновенно при наличии любой ликвидности: Redis-скан объединял оба направления без сверки стороны ордера. Введены направленные сканы ZSET + проверка `side` из HASH + числовая верификация против триггерной цены.
- Market-buy возвращал остаток средств с refund=0.
- Частично исполненный taker-ордер возвращался в книгу полным объёмом (ломались айсберги).
- Phantom-place: задача пушалась в очередь движка до коммита в БД + безусловный maker-settlement. Persist переписан фазами: taker-gate, maker-гарды статуса/оверфилла, self-heal ghost-записей книги; при невалидном тейкере отклоняется весь батч вместо частичного settlement.
- Cancel-race: отмена ордера сериализована с settlement воркера через `SELECT ... FOR UPDATE`; refund размораживает ровно свой `locked_amount`, а не весь лок юзера.
- Резервирование средств: колонка `orders.locked_amount Numeric(36,18)` + миграция с бэкфиллом legacy-ордеров.

**Миграции и инфраструктура:**
- `alembic upgrade head` падал TypeError на `op.execute(text, params)` — параметры инлинятся whitelist-хелпером; `env.py` при DNS-ошибках падает fail-fast с маскированным URL вместо сырого asyncpg-трейсбека.

**Админка:**
- Пересоздание деактивированной торговой пары падало 500 (`ValueError: already exists`). Теперь неактивная пара реактивируется той же строкой с новыми параметрами, активная даёт HTTP 409 `duplicate_trading_pair`; список пар поддерживает `include_inactive`.

**Лента сделок:**
- Время сделок отображалось со сдвигом на часы: REST отдавал миллисекунды, UI читал их как секунды (`ts*1000`); живые WS-принты приходили вообще без `ts`; WS snapshot/pong использовали monotonic-время процесса вместо wall-clock. Введён единый контракт: `ts` = целые epoch-миллисекунды во всех каналах; `formatTime()` стал unit-aware c гвардой пустых и legacy-значений — старые записи localStorage безопасны.

### Изменено

- Семантика активации стоп-ордеров переведена на цену последней сделки как единственный источник триггера: BUY при `last >= stop`, SELL при `last <= stop`, равенство включено (обе стороны могут сработать одновременно). Книга ордеров никогда не активирует стоп («book never arms a stop») — промежуточная touch-семантика по спреду удалена как вырождающаяся (любой стоп «за рынком» становился мгновенным taker). Placement-time оценка через событие `stops_changed` срабатывает только если ценовое условие уже истинно по последней сделке. Defense-in-depth: числовой re-check до конверсии и заморозки средств; заморозка collateral происходит в момент триггера. Trailing-стопы используют живой score-ZSET как триггер.
- Modify лимитного ордера реализован как cancel+place через полный place-конвейер воркера (ранее modify не обрабатывался вовсе).
- `publish_trade` кладёт `ts` в payload события сделки.

### Добавлено

- **Публичная лестница условных заявок («стоп-бук»)** — анонимная агрегированная лестница стопов всех участников по символу: REST `GET /api/v1/market/stops?symbol=...`, WS-инвалидация `stops_changed` через общий канал стакана (без изменений WS-гейтвея), панель «Conditional» в терминале с фонами объёма и счётчиками ×N; trailing-стопы показываются по текущей server-side триггерной цене (дрейф виден). Уровни анонимны — охота за стопами конкретного игрока невозможна.
- **Публичные стопы на свечном графике** — пунктирные полые бары лестницы поверх чарта, слой под маркерами собственных стопов; тумблер «All stops» в легенде графика (настройки персистятся в localStorage).
- **Depth-оверлей графика** — горизонтальные гистограммы объёмов bid/ask поверх цены: per-level объёмы (не кумулятивные), общая правая привязка баров, прозрачность по глубине уровня, меньший объём рисуется последним и всегда виден (алгоритм художника); тумблеры Book / My stops.
- **UX терминала**: клик по уровню стакана автозаполняет цену формы (для stop_market/stop_limit — поле stopPrice); собственные стоп-ордера подсвечиваются маркерами ⚡ в строках стакана и считаются в шапке панели; WS-событие нового стопа мгновенно обновляет список открытых ордеров.
- Юнит-тесты: критические фиксы ядра (10), пересоздание пар админки (4), публичная лестница (8), семантика price-trigger стопов (14), контракт времени сделок (4) — итого **+40 тестов**, базлайн_suite **141 passed / 6 pre-existing failed**.

### Планы (Roadmap)

- Транзакционный outbox (запись событий после коммита БД) и идемпотентность воркера (idempotency-key / replay-nonce).
- Восстановление книги ордеров из PostgreSQL при рестарте воркера.
- Security hardening: TLS, BFF/session-cookie вместо `api_secret` в localStorage с клиентским HMAC, rate-limit на логины, fail-fast дефолтного `APP_SECRET`.
- Показ чужих условных заявок владельцам аккаунтов (нужен дизайн против front-running).
- Trailed-цена trailing-стопа пока живёт только в Redis сервера — собственный маркер на графике показывает цену размещения.
